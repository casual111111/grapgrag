# 电销上下文（Telesale Context）业务知识库

> 本文档基于对限界上下文「电销上下文」源代码的逆向还原与分析，以业务叙事语言结构化沉淀该领域的业务知识，不包含任何技术实现细节，面向业务人员、运营人员、产品经理及业务系统对齐。
>
> 电销上下文是现金贷业务中的「主动营销与催收前置」环节：系统从注册、授信、申请、结清、逾期等各业务节点上"捞"出尚未完成借贷闭环的客户，按规则分配给人工坐席或人工智能（AI）机器人外呼，推动客户完成认证、绑卡、申请、取款或复贷，并对逾期/可展期客户进行外呼催收。
>
> **业务影响范围总览**：注册转化、授信转化、申请转化、放款取款、复贷续贷、逾期催收、营销短信、运营报表。

---

## 1. 业务术语表

### 1.1 电销客户（Call Sale Consumer）
- **业务定义**：在借贷业务流转中、尚未完成当前阶段闭环、被系统识别为有潜在贷款需求且"值得主动联络推动"的自然人主体，是电销工作的唯一对象。可以是平台已有会员，也可以是外部导入的潜在用户。
- **身份特征**：每个电销客户有唯一的客户ID，同时以"手机号 + 归属应用（App/平台）"为唯一业务键（同一手机号在不同应用下视为不同电销客户）。记录其手机号、姓名、性别、年龄、证件号、银行账号等基础画像，以及来源类型、当前状态、分配时间、跟进人等关键信息。客户来源多样，涵盖平台各业务环节的流失或沉睡用户。
- **业务影响范围**：电销全链路（从名单发现、机审、派单、跟进、外呼、废弃审核、状态提醒，到导入与模型评分、报表统计）、电销营销、客户转化、用户增长。

### 1.2 电销客户来源类型（Call Sale Consumer Source Type）
- **业务定义**：描述电销客户"为何进入电销名单"的业务成因标签，标识客户是通过什么渠道或场景进入电销列表的，决定该客户应被推动去做什么，并对应不同的营销策略和跟进优先级。同一客户随业务推进，来源类型会被刷新。
- **来源类型列表（共16类）**：
  - 文件导入（FILE_IMPORT / 0）：通过外部文件批量导入的潜在客户（外部客户）
  - 认证未完成（NOTCERTIFICATION / 1）：注册但未完成身份认证的会员（平台用户）
  - 待绑卡（NOTBINDCARD / 2）：完成认证但未绑定银行卡的会员（平台用户）
  - 待申请（NOTAPPLICATION / 3）：完成绑卡但未提交贷款申请的会员（平台用户）
  - 授信未申请（ASSESS_NO_LOAN / 4）：获得授信额度但未申请贷款的会员（平台用户）
  - 授信未申请2（ASSESS_NO_LOAN2 / 5）：授信未申请衍生（平台用户）
  - 待申请2（NOTAPPLICATION2 / 6）：待申请衍生（平台用户）
  - 结清未复贷（NORELOAN / 14）：贷款已结清但未再次申请的会员（复贷客户）
  - 结清未复贷2（NORELOAN2 / 15）：结清未复贷衍生（复贷客户）
  - 拒绝到期（REFUSEEDEXPIRE / 17）：申请被拒绝后到期可重新申请的会员（召回客户）
  - 机器人转人工（ROBOTTOHUMAN / 20）：AI外呼机器人转接给人工处理的客户（外呼客户）
  - 可展期订单（CANEXTEND / 25）：有逾期订单但可申请展期的会员（逾期客户）
  - 注册未申请（REGISTERED_WITHOUT_APPLY / -1）：注册后未做任何申请的会员（新用户）
  - 放弃/取消（INTERRUPTED_APPLY / -2）：申请过程中放弃取款或取消的会员（流失客户）
  - 完成未申请（FINISHED_WITHOUT_APPLY / -4）：贷款结清后未再申请的会员（复贷客户）
  - 回退（ROLLBACK / -5）：申请被回退后未重新提交的会员（流失客户）
- **业务影响范围**：电销营销、客户分类、精准营销。

### 1.3 电销客户状态（Call Sale Consumer Status）
- **业务定义**：电销客户在电销流水线/流程中所处的业务阶段标记，反映客户从进入电销列表到最终完成或废弃的全过程。由业务动作驱动切换，非系统自动空转。
- **状态列表（共7个阶段）**：
  - 等待机审（WAIT_MACHINE_EVA / 1）：新进入电销列表，等待风控引擎审核（非终结态）
  - 等待分配（WAIT_DISPATCH / 2）：机审通过，等待分配给电销人员（非终结态）
  - 待处理（WAIT_FOLLOW / 3）：已分配给电销人员，等待电话跟进（非终结态）
  - 已处理（FOLLOWED / 4）：电销人员已跟进，后续可继续跟进（非终结态）
  - 已暂停（PAUSED / 5）：暂停跟进，暂不处理（非终结态）
  - 已完成（FINISH / 6）：电销跟进完成，客户已成功转化或无需再跟进（终结态）
  - 已废弃（ABANDONED / 9）：客户被判定为无效，废弃处理（终结态）
- **业务影响范围**：电销流程、跟进管理、客户生命周期。

### 1.4 电销坐席
- **业务定义**：承担人工外呼与跟进的运营人员。
- **核心特征**：区分"人工坐席"与"机器人坐席"两类；坐席可配置"单日接单上限"，超额当日不再派单。机器人坐席名带特殊标识，承担 AI 外呼与机审拒绝的"申请人"角色。

### 1.5 坐席分组
- **业务定义**：按业务能力/负责的逾期层级/应用归属对坐席进行编组，用于派单范围控制与报表口径。
- **核心特征**：一个分组绑定多个坐席、多个逾期层级、多个应用，是派单与统计的聚合单元。

### 1.6 电销派单记录（Call Sale Dispatch Log）
- **业务定义**：记录"某电销客户在何时被派给哪位坐席"的责任归属凭证/操作记录。
- **核心特征**：携带派单方（分配人）、坐席、派单时间（分配时间）、操作员、备注等信息；是坐席当日接单量统计、案件归属、回收释放、工作量统计、绩效考核的依据。
- **业务影响范围**：电销分配、工作量统计、绩效考核。

### 1.7 电销跟进记录（Call Sale Follow Log）
- **业务定义**：坐席对电销客户执行一次外呼/联络后产出的结果记录/跟进日志，是电销过程的"业务流水"。
- **核心特征**：携带跟进结果类型、结果明细（详细结果）、坐席、附件（录音/截图）、备注、废弃原因类型等信息。跟进结果类型包括：接通（CONNECTED）、未接通、有意向、无意向、承诺还款、其他。已跟进客户中"被回收"的，手机号会被脱敏展示。
- **业务影响范围**：电销跟进、客户管理、绩效考核。

### 1.8 电销发现服务（Call Sale Discover Service）
- **业务定义**：系统定时任务，自动扫描平台各业务环节的数据，发现有潜在贷款需求的客户并将其加入电销列表的服务。
- **发现场景**：包括注册未申请、认证未完成、待绑卡、待申请、授信未申请、结清未复贷、拒绝到期、回退未申请、机器人转人工、可展期。
- **业务影响范围**：电销客户获取、用户转化、营销自动化。

### 1.9 电销派发（Call Sale Dispatch）
- **业务定义**：将电销客户按照规则分配给电销人员的过程，分为系统自动分配和人工分配两种方式。
- **分配方式**：
  - 自动分配：系统定时任务根据电销人员的当前负载、分配类型、权重等规则自动分配
  - 人工分配：管理员在后台手动将客户分配给指定的电销人员
- **业务影响范围**：电销分配、电销员工作量管理。

### 1.10 电销废弃申请（Call Sale Abandon Apply）
- **业务定义**：当电销客户无法继续推动（如多次联系不上、明确拒绝、风险客户，或电销人员认为某个客户无效/不值得继续跟进）时，由坐席或机器人发起的"放弃该客户"申请，需审核/审批才生效。
- **废弃原因**：空号、停机、非本人、无意向、重复客户。
- **状态/审批流程**：提交废弃申请 -> 待审批/待处理（PENDING）-> 通过（PASS）/ 拒绝（REJECT）/ 否决 / 删除。机器人机审拒绝也会自动生成一条"已通过"的废弃申请。
- **业务影响范围**：电销客户管理、客户质量管控。

### 1.11 电销机审（Call Sale Machine Audit）
- **业务定义**：新进入电销列表的客户在分配给电销人员之前，由风控引擎进行自动风险评估的过程。
- **审核结果**：通过则进入待分配状态；拒绝则直接进入废弃状态。
- **业务影响范围**：电销分配、客户质量、风险控制。

### 1.12 电销外呼（Call Sale Outer Call）与外呼任务记录
- **业务定义**：通过AI机器人外呼平台，对电销客户进行自动外呼，识别客户意向后再转接给人工电销人员的流程。
- **业务流程**：客户导入外呼平台 -> AI机器人外呼 -> 识别有意向 -> 转人工跟进。
- **外呼任务记录**：当坐席为机器人、或对可展期客户走 AI 外呼时，向外部 AI 外呼平台下发的外呼指令凭证。以"客户+任务+坐席"为幂等键，7 天内已成功外呼的不重复下发；携带平台、客户姓名、逾期天数、逾期金额等外呼变量。
- **业务影响范围**：电销效率、客户触达、AI外呼。

### 1.13 备用手机号
- **业务定义**：为主手机号无法接通的电销客户登记的备选联络号码。
- **核心特征**：与电销客户一一对应可多条，用于提升联络触达率。

### 1.14 状态提醒
- **业务定义**：以手机号为键、按"APP 登陆/认证未完成/申请"三类提醒场景缓存的高优先级客户提醒标记，供坐席工作台按提醒维度筛选。
- **核心特征**：存于缓存、带时间戳，客户提交申请后自动清除相关提醒。

### 1.15 导入任务
- **业务定义**：运营通过上传文件批量导入外部名单（如第三方引流名单）生成电销客户的批次凭证。
- **核心特征**：携带文件、归属应用、操作人、处理状态与结果描述；导入后异步扫描入电销池。

### 1.16 模型执行任务
- **业务定义**：对电销客户跑评分模型（如新用户模型评分）的批量执行批次，产出评分用于排序/筛选。
- **核心特征**：可导出明细，是电销客户优先级排序的算力来源。

### 1.17 电销配置（Call Sale Config）
- **业务定义**：电销业务的各项配置参数/运营可随时调整的业务旋钮集合，按分组管理，用于控制电销业务流程的各个环节（如发现窗口、派单比例、展期天数等）。
- **核心特征**：每项含编码、名称、取值、单位、是否对外可见、所属分组；部分配置可见性可控。
- **业务影响范围**：电销运营、流程管理。

**业务影响范围总结**：上述术语覆盖电销全链路——从名单发现、机审、派单、跟进、外呼、废弃审核、状态提醒，到导入与模型评分、报表统计、电销营销、客户转化、用户增长、精准营销、流程管理。

## 2. 业务约束清单

1. **同一客户在系统中存在未完成订单，或上一次申请被拒绝，则不得派单**
   - **适用场景**：派单前对每一位"等待分配"的电销客户做前置校验时。
   - **约束内容**：若该手机号在对应应用（APP）下有未完成订单，或最近一次申请处于被拒状态，必须成立"拦截"。
   - **违规后果**：该客户被置为"已暂停"，当日不再派发，避免对已在流程中的客户重复打扰或冲突。
   - **业务影响范围**：申请、放款、催收主流程。

2. **电销客户入池排重**
   - **适用场景**：系统发现新客户并加入电销列表时。
   - **约束内容**：同一手机号在同一应用包（APP）下，不能重复加入电销列表。系统需进行排重处理，防止同一客户重复进入电销流程。
   - **违规后果**：重复客户导致电销资源浪费，客户被多次骚扰。
   - **业务影响范围**：电销客户发现、客户管理。

3. **坐席单日接单量不得超过其配置上限**
   - **适用场景**：每日派单时统计每位坐席当日已派单量，或系统自动分配电销客户给电销人员时。
   - **约束内容**：坐席当日已派客户数 ≥ 其配置的每日分配上限（call_sale_limit）时，必须从候选坐席中剔除，超出上限后不再分配新客户。
   - **违规后果**：该坐席当日不再分得新客户，保障坐席跟进质量、防止超载，避免电销员工作量超载导致跟进不及时或跟进质量下降。
   - **业务影响范围**：坐席管理、电销分配、电销员工作量管理、合规。

4. **电销跟进权限控制**
   - **适用场景**：电销人员对分配的客户进行跟进操作时。
   - **约束内容**：电销人员只能跟进分配给自己的客户（通过跟进人标识（followerId）匹配），不能跟进其他电销人员的客户或未分配的客户。
   - **违规后果**：跟进操作被拒绝，提示权限不足。
   - **业务影响范围**：电销跟进、客户分配、权限管理。

5. **同一外呼指令 7 天内不重复下发**
   - **适用场景**：向外部 AI 外呼平台下发外呼任务前。
   - **约束内容**：若该客户+任务+坐席组合在近 7 天已有外呼记录且非"失败"状态，不得重复下发。
   - **违规后果**：跳过本次外呼，避免重复拨打扰民与外呼成本浪费。
   - **业务影响范围**：外呼成本与体验。

6. **外呼手机号必须合法有效**
   - **适用场景**：发起 AI 外呼前校验号码。
   - **约束内容**：号码经国家码替换与合法性校验后必须通过。
   - **违规后果**：外呼失败、记录失败状态，触发失败重投流程，不向无效号码外呼。
   - **业务影响范围**：外呼成本与体验。

7. **可展期客户自动展期外呼量受比例上限约束**
   - **适用场景**：对"可展期订单"来源客户做自动展期外呼时。
   - **约束内容**：当日自动展期外呼量 ≤ （自动展期比例 ÷ 100 × 当日可展期客户总量）。
   - **违规后果**：超过上限后当日停止对该来源客户的自动展期外呼，控制催收外呼节奏与成本。
   - **业务影响范围**：申请、放款、催收主流程。

8. **电销废弃申请审批与生效规则**
   - **适用场景**：坐席发起废弃申请、或机器人机审拒绝时。
   - **约束内容**：废弃申请需要经过审批流程，不能直接废弃。人工废弃申请须经审核通过才将客户置为"已废弃"；机审拒绝由机器人自动生成"已通过"的废弃申请直接生效。已存在待审批或已通过的废弃申请的客户，不能重复提交废弃申请。
   - **违规后果**：未经审核通过的废弃申请不改变客户状态，防止客户被错误废弃造成潜在客户流失；已通过的废弃使客户退出电销池，可被"回收"重新进入。
   - **业务影响范围**：电销废弃、客户管理、审批流程、合规。

9. **电销客户状态流转限制**
   - **适用场景**：电销客户状态变更时。
   - **约束内容**：电销客户状态需按规定的流程流转，不能跳跃或逆向流转。例如，已废弃的客户不能重新变为待处理状态。
   - **违规后果**：状态错误导致客户被错误处理或遗漏跟进。
   - **业务影响范围**：电销流程、客户生命周期管理。

10. **客户提交借贷申请后，其名下电销客户必须收口完成**
    - **适用场景**：客户在 App 提交借贷申请事件触发时。
    - **约束内容**：该手机号在该应用（APP）下、所有非"申贷完成来源"且非"完成/废弃"状态的电销客户，必须统一置为"完成"，并清除其所有状态提醒。
    - **违规后果**：若未收口，会出现"已申请客户仍被电销打扰"的合规与体验问题。
    - **业务影响范围**：申请、放款、催收主流程。

11. **报表查询区间不得超过 180 天**
    - **适用场景**：电销报表、电销员报表、短信报表查询与导出。
    - **约束内容**：查询起止时间跨度 ≤ 180 天，且结束时间不得晚于当前时间。
    - **违规后果**：查询被拒绝并提示，防止超大区间拖垮统计性能。
    - **业务影响范围**：运营报表。

12. **被回收案件的手机号必须脱敏展示**
    - **适用场景**：坐席工作台展示已跟进客户列表时。
    - **约束内容**：凡标记为"已回收"的客户，手机号必须部分隐藏。
    - **违规后果**：保障回收案件客户隐私，防止坐席私自留存号码。
    - **业务影响范围**：坐席管理与合规。

## 3. 生命周期里程碑

电销客户从“被发现/导入”到“完成或废弃”的关键业务阶段，及阶段切换的业务触发条件。生命周期贯穿注册转化、授信转化、申请转化、复贷、催收各环节，是电销产能与转化率统计的口径基础。

### 3.1 电销客户生命周期

系统发现新客户（通过发现服务或文件导入）后，进入以下生命周期状态流转：

| 阶段状态 | 业务含义 | 进入下一阶段的业务触发条件 |
|---|---|---|
| **诞生（发现/导入）** | 客户被系统从某业务节点捞入电销池，或运营通过文件导入名单生成。设置来源类型，初始状态为等待机审。 | 被纳入机审批次。部分来源（如机器人转人工、可展期）可跳过机审直接进入“等待分配”。 |
| **等待机审（WAIT_MACHINE_EVA / 1）** | 客户等待风控引擎进行风险评估，机审判定是否可进入人工电销。 | 机审通过 → 进入“等待分配”；机审拒绝 → 直接进入“已废弃”。 |
| **等待分配（WAIT_DISPATCH / 2）** | 已通过机审，等待被派给某位坐席（人工或机器人）。 | 派单任务运行，按来源权重与应用归属匹配到坐席，或进行自动/人工分配 → 进入“待跟进”。<br>• **自动分配**：系统定时任务自动分配给电销人员。<br>• **人工分配**：管理员在后台手动分配。 |
| **待跟进（WAIT_FOLLOW / 3）** | 已落到具体坐席名下（待打电话），等待坐席执行外呼/联络。 | 坐席完成一次外呼并录入跟进结果 → 进入“已跟进”；或提交废弃申请 → 进入“废弃申请审批中”。 |
| **已跟进（FOLLOWED / 4）** | 坐席已对该客户执行过至少一次外呼/联络并留下跟进记录（已打电话）。客户可能已申请贷款或承诺后续申请。 | • **跟进完成（有意向）**：记录跟进日志，可继续跟进或等待客户转化。客户在 App 提交借贷申请 → 触发收口进入“已完成”。<br>• **跟进完成（无意向）**：记录跟进日志，可继续跟进或提交废弃申请 → 进入“废弃申请审批中”。<br>• **被回收**：回到“等待分配”。 |
| **已暂停（PAUSED / 5）** | 临时不处理，暂停期间不处理。 | 待条件满足后，可恢复进入“待跟进”。<br>• **系统暂停**：因系统中已有未完成订单或上次被拒。待原订单完结/拒绝状态变化后，可被重新发现或回收。<br>• **人工暂停**：电销人员或管理员手动暂停跟进。 |
| **废弃申请审批中（PENDING）** | 电销人员提交废弃申请，等待审批。 | 审批通过 → 进入“已废弃”；审批拒绝 → 回到“待跟进”。 |
| **已完成（FINISH / 6）** | 客户已在 App 提交申请，成功转化，电销使命达成，退出电销池。 | 终态。后续如结清未复贷、可展期，会作为“新来源”重新发现进入新一轮电销。 |
| **已废弃（ABANDONED / 9）** | 客户无效，退出电销池。 | 可经“回收”动作回到“等待分配”重新跟进。<br>• 机审拒绝。<br>• 人工或机器人发起废弃且审核通过。 |

### 3.2 电销客户发现生命周期

各业务场景发生（会员注册、认证、绑卡、申请、放款、还款、结清、逾期）后，触发客户发现流程：
1. **发现服务定时扫描**：每日/每小时扫描各业务环节的数据，识别符合条件的潜在客户。
2. **排重判断**：判断客户是否已存在电销列表，通过“手机号 + APP包”进行排重。
3. **创建记录**：创建电销客户记录，设置来源类型，状态初始化为“等待机审（WAIT_MACHINE_EVA / 1）”。
4. **进入流程**：进入电销流程，开始“等待机审 → 分配 → 跟进”的生命周期。

### 3.3 电销跟进日志生命周期

电销人员进行电话跟进（拨打电话、沟通、记录结果）时，触发跟进日志生命周期：
1. **创建跟进日志（首次跟进）**：记录跟进结果、详细结果、备注、附件。更新客户状态为“已跟进（FOLLOWED / 4）”。
2. **后续跟进（可选）**：编辑现有跟进日志（编辑模式），或创建新的跟进日志。
3. **跟进完成**：
   - 客户成功转化：标记为“已完成（FINISH / 6）”。
   - 客户无效：提交废弃申请，进入“废弃申请审批中（PENDING）”。

## 4. 业务事件目录

### 4.1 电销客户发现
- **发生场景**：系统定时任务扫描发现新的潜在电销客户，包括注册未申请、认证未完成、待绑卡、待申请、授信未申请、结清未复贷、拒绝到期、回退未申请、机器人转人工、可展期场景。
- **携带的关键业务信息**：客户手机号、应用程序 (APP) 包标识 (ID)、来源类型、来源会员标识 (ID)、来源申请标识 (ID)、生成时间、是否是复贷客户。
- **后续业务影响**：创建电销客户记录，状态为等待机审；进入电销流程。

### 4.2 客户提交借贷申请
- **发生场景**：客户在应用程序 (App) 完成借贷申请提交时。
- **携带的关键业务信息**：客户手机号、归属应用、申请单号、授信基础信息。
- **后续业务影响**：该客户名下所有未完成电销客户收口为"完成"、清除状态提醒；若存在"已派单但未跟进"记录，触发"未电销已申请"补登记；关联推送点击记录与短信发送手机号关系到申请单；清理客户特定标签。影响：电销转化统计、坐席未跟进率考核、推送归因。

### 4.3 电销客户文件导入
- **发生场景**：运营人员通过上传文件批量导入外部潜在客户到电销列表，异步处理完成时。
- **携带的关键业务信息**：导入任务标识 (ID)、文件、归属应用、处理状态、结果描述、客户手机号、姓名、性别、年龄、证件号、银行卡号、导入时间。
- **后续业务影响**：名单入电销池成为"文件导入"来源客户；创建电销客户记录，状态为等待机审；记录导入任务。影响：外部引流名单转化。

### 4.4 状态提醒触发
- **发生场景**：客户出现"应用程序 (APP) 登陆"、"认证未完成"、"申请"高价值状态时。
- **携带的关键业务信息**：手机号、提醒类型、时间戳。
- **后续业务影响**：写入缓存供坐席工作台按提醒维度筛选优先跟进。影响：精准触达、转化提升。

### 4.5 来源刷新
- **发生场景**：发现任务将客户按新成因重新纳入电销池时。
- **携带的关键业务信息**：新来源类型、归零跟进人、状态置"等待分配"。
- **后续业务影响**：同一客户以新身份重新进入派单，旧的归属与提醒被清理。影响：复贷/展期/催收轮次管理。

### 4.6 电销机审完成
- **发生场景**：风控引擎/风控机审对电销客户完成自动风险评估/判定为拒绝时。
- **携带的关键业务信息**：客户标识 (ID)、客户、机审结果（通过、拒绝）、机审结果描述、命中的风控规则码。
- **后续业务影响**：机审通过则客户进入待分配状态；机审拒绝则客户置"已废弃"、直接进入废弃状态，自动生成机器人发起的"已通过"废弃申请。影响：电销池规模、风控拦截统计。

### 4.7 模型评分执行
- **发生场景**：对电销客户批量跑评分模型时。
- **携带的关键业务信息**：任务、评分结果。
- **后续业务影响**：评分用于客户优先级排序与筛选，可导出明细。影响：电销效率、名单质量。

### 4.8 电销客户自动分配
- **发生场景**：系统定时任务/派单任务将待分配的客户按规则自动分配/落到坐席名下时。
- **携带的关键业务信息**：客户标识 (ID) 列表、客户、电销员标识 (ID)/坐席、分配时间/派单时间、分配类型、派单方、备注。
- **后续业务影响**：客户状态更新为待处理；写入派单记录、坐席当日接单量累加、可展期来源计入当日自动展期外呼计数；电销员收到客户列表；记录派发日志。影响：坐席产能、案件归属、外呼节奏。

### 4.9 电销客户人工分配
- **发生场景**：管理员在后台将客户手动分配给指定的电销人员。
- **携带的关键业务信息**：客户标识 (ID) 列表、电销员标识 (ID)、分配人、分配时间、备注。
- **后续业务影响**：同自动分配，客户状态更新为待处理。

### 4.10 电销跟进
- **发生场景**：电销人员/坐席外呼/联络/电话跟进后录入/记录跟进结果时。
- **携带的关键业务信息**：电销员标识 (ID)/坐席、客户标识 (ID)/客户、跟进结果类型（接通、未接通）、详细结果/结果明细、备注、附件（文件标识 (ID)）、废弃原因。
- **后续业务影响**：创建跟进日志/写入跟进记录；客户状态更新为已处理/置"已跟进"；如跟进结果为接通，可发送跟进短信；若结果为废弃则发起废弃申请。影响：转化漏斗、坐席绩效、客户触达率。

### 4.11 电销跟进编辑
- **发生场景**：电销人员对已存在的跟进日志进行编辑修改。
- **携带的关键业务信息**：跟进日志标识 (ID)、修改后的跟进结果、备注。
- **后续业务影响**：更新跟进日志，不影响客户状态。

### 4.12 电销废弃申请提交
- **发生场景**：电销人员认为客户无效，提交废弃申请。
- **携带的关键业务信息**：客户标识 (ID)、废弃原因类型、废弃原因描述、申请人、申请时间、附件。
- **后续业务影响**：创建废弃申请记录，状态为待审批；等待审批人处理。

### 4.13 电销废弃申请审批
- **发生场景**：审批人/审核人对电销废弃申请进行审批/作出裁决（通过、拒绝/否决）时。
- **携带的关键业务信息**：废弃申请标识 (ID)/申请单、审批结果/通过/否决、审批人/审核人、审批时间/审核时间。
- **后续业务影响**：审批通过则客户状态变为废弃/置"已废弃"退出电销池；审批拒绝/否决则客户状态恢复为待处理/保留继续跟进。影响：电销池规模、合规留痕。

### 4.14 电销外呼导入
- **发生场景**：系统将电销客户导入人工智能 (AI) 外呼平台/向外部人工智能 (AI) 外呼平台下发外呼任务返回成功时，发起自动外呼。
- **携带的关键业务信息**：客户标识 (ID)/客户、手机号、外呼任务标识 (ID)/任务、电销员标识 (ID)/坐席、批次号、状态、备注。
- **后续业务影响**：人工智能 (AI) 机器人执行外呼；识别客户意向；有意向的客户转人工跟进；成功则记外呼记录为"已发送"、避免 7 天内重复下发。影响：外呼触达、成本。

### 4.15 电销外呼失败处理
- **发生场景**：人工智能 (AI) 外呼平台外呼失败（如空号、停机、无人接听）/向外部人工智能 (AI) 外呼平台下发外呼任务返回失败时，需要重新导入或标记。
- **携带的关键业务信息**：外呼记录标识 (ID)、失败原因、外呼任务标识 (ID)、客户、任务、坐席、批次号、状态。
- **后续业务影响**：外呼失败记录被标记；失败则记失败状态并进入失败重投流程；可重新导入外呼或由电销员人工跟进。影响：失败重试。

### 4.16 电销短信发送
- **发生场景**：电销人员跟进客户后，系统自动或手动向客户发送跟进短信。
- **携带的关键业务信息**：客户手机号、短信模板编码、短信参数、应用程序 (APP) 包。
- **后续业务影响**：客户收到跟进短信；记录短信发送历史。

### 4.17 电销客户释放
- **发生场景**：管理员将已分配给电销人员的客户释放，使其重新进入待分配状态。
- **携带的关键业务信息**：客户标识 (ID) 列表、原电销员标识 (ID)、释放人、释放原因。
- **后续业务影响**：客户状态恢复为待分配；原电销员的分配记录被标记为删除。

### 4.18 电销客户移除
- **发生场景**：管理员将客户从电销列表中彻底移除。
- **携带的关键业务信息**：客户标识 (ID) 列表、移除人、移除原因。
- **后续业务影响**：客户从电销列表中删除，不再参与电销流程。

**业务影响范围**：事件串起"发现→机审→派单→跟进→外呼→收口/废弃"全链路，是运营监控大盘与坐席绩效的数据来源。

## 5. 业务计算规则

### 5.1 电销客户来源类型判断
- **判断逻辑**：根据客户在平台上的行为路径，确定其对应的来源类型：
  - 注册后未完成认证 -> 认证未完成（NOTCERTIFICATION）
  - 完成认证后未绑卡 -> 待绑卡（NOTBINDCARD）
  - 完成绑卡后未提交申请 -> 待申请（NOTAPPLICATION）
  - 获得授信额度后未申请 -> 授信未申请（ASSESS_NO_LOAN）
  - 贷款结清后未再次申请 -> 结清未复贷（NORELOAN）
  - 申请被拒绝到期后未重新申请 -> 拒绝到期（REFUSEEDEXPIRE）
  - 申请过程中放弃取款或取消 -> 放弃/取消（INTERRUPTED_APPLY）
  - 申请被回退后未重新提交 -> 回退（ROLLBACK）
  - 注册后完全无操作 -> 注册未申请（REGISTERED_WITHOUT_APPLY）
- **用途**：用于确定客户进入电销列表的原因，影响营销策略和跟进优先级。
- **业务影响范围**：电销客户发现、客户分类、精准营销。

### 5.2 坐席（电销员）当日接单量与分配控制
- **计算公式**：
  - 坐席当日接单量 = 当日该坐席名下新增的派单记录条数
  - 是否可分配 = 电销员当日已分配数量 < 电销员每日上限（call_sale_limit）
- **变量含义与说明**：
  - 坐席当日接单量：以当日派单记录按坐席聚合计数。
  - 电销员当日已分配数量：当天已分配给该电销员的客户数量。
  - 电销员每日上限：电销员个人配置的每日最大分配数量。
- **用途**：与坐席单日接单上限比较，超额坐席当日退出派单候选；用于控制电销员的工作负载，确保跟进质量。影响派单均衡与坐席负载。
- **业务影响范围**：派单计数影响坐席管理、电销员工作量管理。

### 5.3 当日可自动展期外呼量上限
- **计算公式**：当日自动展期外呼量上限 = ⌊自动展期比例 ÷ 100⌋ × 当日可展期客户总量
- **变量含义**：自动展期比例为运营配置项（默认 100，即全量；可调低以缩量）；当日可展期客户总量为近 30 天内、来源为"可展期订单"、状态"等待分配"的客户数。
- **用途**：控制当日对可展期（逾期）客户的自动展期外呼节奏，平衡催收强度与外呼成本。影响催收外呼量与成本。
- **业务影响范围**：催收成本与转化效率。

### 5.4 来源权重派单优先级
- **排序逻辑**：派单优先级 = 按"来源权重顺序表"由前到后依次匹配。按照客户来源类型的权重顺序，优先分配权重高的客户类型。
- **来源权重顺序表**（由高到低）：
  1. 可展期订单（CANEXTEND）
  2. 文件导入（FILE_IMPORT）
  3. 认证未完成（NOTCERTIFICATION）
  4. 授信未申请（ASSESS_NO_LOAN）
  5. 授信未申请2（ASSESS_NO_LOAN2）
  6. 待申请（NOTAPPLICATION）
  7. 待申请2（NOTAPPLICATION2）
  8. 结清未复贷（NORELOAN）
  9. 结清未复贷2（NORELOAN2）
  10. 拒绝到期（REFUSEEDEXPIRE）
  11. 机器人转人工（ROBOTTOHUMAN）
- **变量含义**：每一轮派单按该固定权重顺序，逐来源类型、逐应用地取出"等待分配"客户，按坐席候选（人工/机器人）派发。
- **用途**：确保高价值/高紧迫来源（如可展期逾期、导入名单）优先被外呼，提升资源投放精度；确保高价值客户优先跟进。影响整体转化与催收回收。
- **业务影响范围**：电销分配、客户优先级、整体转化与催收回收。

### 5.5 电销客户优先级排序（同来源内）
- **计算公式**：同来源内取客户时按"创建时间倒序"取（最新入池者优先）
- **用途**：同来源、同应用下，最新进入电销池的客户优先派发，保证新鲜线索先触达。影响线索时效与转化率。

### 5.6 模型评分（电销客户优先级评分）
- **计算公式**：电销客户评分 = 由风控评分模型（如新用户模型）对该客户画像特征计算得出
- **变量含义**：评分模型以电销客户画像（含来源、基础信息、行为特征等）为输入，输出分数；属风控特征计算范畴。
- **用途**：用于电销客户排序、筛选与名单质量评估；可批量执行并导出明细。影响电销投放效率与风控前置。

### 5.7 电销废弃申请状态判断
- **判断逻辑**：如果客户已有待审批或已通过的废弃申请，则不能重复提交废弃申请。
- **计算公式**：是否可以提交废弃 = 无待审批（PENDING）且无通过（PASS）的废弃申请记录
- **用途**：用于防止重复提交废弃申请，确保废弃流程的规范性。
- **业务影响范围**：电销废弃、审批流程。

> **说明**：本上下文中电销客户状态、来源类型等均为业务枚举（非数值计算），主要"算账逻辑"集中在派单计数、展期比例与权重排序上；金额/天数类数值（如逾期天数、逾期金额）由借贷主域提供，电销侧仅作为外呼变量透传。

**总体业务影响范围**：派单计数影响坐席管理；展期比例与权重排序影响催收成本与转化效率；评分影响名单质量；来源类型判断影响精准营销；废弃申请判断影响审批流程规范性。

## 6. 业务配置项手册

### 6.1 自动展期外呼比例
- **业务作用**：控制当日对"可展期订单"客户自动展期外呼量占当日可展期总量的比例。
- **默认/取值**：默认 100（即 100%）。
- **调整影响**：调低则当日展期外呼缩量，影响催收外呼量、外呼成本与回款节奏；需与催收策略同步。
- **变更影响面**：催收与转化主流程、催收外呼量、外呼成本、回款节奏。

### 6.2 展期外呼天数窗口
- **业务作用**：控制"可展期订单"客户的发现/外呼时间窗口（以天数为单位界定可展期范围）。
- **默认/取值**：运营设定。
- **调整影响**：影响可展期客户池规模与催收时效；窗口放大则更多逾期客户进入外呼。
- **变更影响面**：可展期客户池规模、催收时效、逾期客户外呼量。

### 6.3 各来源发现窗口与延迟
- **业务作用**：控制每类来源（认证未完成/待申请/结清未复贷/拒绝到期/机器人转人工/可展期）从业务节点发生到进入电销池的时间延迟与扫描区间。
- **默认/取值**：每来源独立配置「起始偏移」「结束偏移」。
- **调整影响**：调小延迟则客户更早被电销（提升时效但可能打扰）；调大则更克制。影响各来源触达节奏与合规。
- **变更影响面**：各来源触达节奏、合规、客户进入电销池时间。

### 6.4 来源生效应用与平台范围
- **业务作用**：控制某来源只从指定应用/平台发现客户，避免跨平台误捞。
- **默认/取值**：每来源独立配置「应用列表」「平台列表」。
- **调整影响**：调整会改变各平台电销名单来源构成，影响各应用转化与名单量。
- **变更影响面**：各平台电销名单来源构成、各应用转化、名单量。

### 6.5 坐席单日接单上限/电销员每日上限配置（call_sale_limit）
- **业务作用**：控制每位坐席/电销人员当日/每天最多可被分配的新客户数量。
- **默认/取值**：按坐席设定。
- **建议取值范围**：20~100 个/天。
- **调整影响**：调高/上限越高，则坐席负载增大、处理压力越大、可能跟进不深，但客户分配效率更高；调低/上限越低，则派单更分散、电销员工作负荷更均衡。影响跟进质量、坐席产能与客户跟进时效。
- **变更影响面**：电销分配、坐席/电销员工作量、客户跟进时效、跟进质量与坐席产能。

### 6.6 电销客户来源类型配置
- **业务作用**：配置哪些来源类型的客户需要进入电销列表，以及各来源类型的优先级权重。
- **默认/取值**：由运营团队根据各来源类型的转化率确定。
- **调整影响**：开启或关闭某些来源类型会影响电销客户的数量和质量。
- **变更影响面**：电销客户发现、客户数量、转化率。

### 6.7 机器人坐席标识
- **业务作用**：用于在派单时识别坐席为"机器人"还是"人工"，决定走人工智能（AI）外呼还是人工跟进。
- **默认/取值**：约定名（含特定关键字）。
- **调整影响**：变更需同步派单逻辑与外呼通道；误判会导致人工坐席被当机器人派单或反之。
- **变更影响面**：派单逻辑、外呼通道、坐席身份识别。

### 6.8 电销自动分配开关配置
- **业务作用**：控制电销人员是否参与电销客户的自动分配。
- **默认/取值**：开启（true）/ 关闭（false）。
- **调整影响**：开启自动分配后，系统将待分配客户按规则自动分配给电销员；关闭后，电销员只能通过人工分配获得客户。
- **变更影响面**：电销分配、电销员工作量。

### 6.9 电销外呼任务配置
- **业务作用**：配置人工智能（AI）外呼平台的任务标识（ID），以及哪些类型的电销客户需要导入外呼平台进行自动外呼。
- **默认/取值**：由运营团队根据外呼成本和转化效果确定。
- **调整影响**：开启或关闭外呼会影响电销效率和成本。
- **变更影响面**：电销外呼、电销成本、客户触达。

### 6.10 状态提醒开关与类型
- **业务作用**：控制哪些客户状态变化会写入高优先级提醒缓存供坐席优先筛选。
- **默认/取值**：应用程序（APP）登陆/认证未完成/申请 三类。
- **调整影响**：调整影响坐席工作台优先跟进名单与触达精度。
- **变更影响面**：坐席工作台优先跟进名单、触达精度、精准触达。

### 6.11 电销废弃申请审批流程配置
- **业务作用**：配置电销废弃申请是否需要审批，以及审批人、审批规则。
- **默认/取值**：由运营团队根据客户质量管理策略确定。
- **调整影响**：开启审批流程可控制客户废弃质量，但会增加审批工作量；关闭审批流程则电销员可直接废弃客户。
- **变更影响面**：电销废弃、客户质量、审批流程。

### 6.12 电销跟进短信模板配置
- **业务作用**：配置电销人员跟进客户后自动发送的短信模板。
- **默认/取值**：由运营团队根据营销文案策略确定。
- **调整影响**：修改短信模板内容会影响客户收到的跟进短信文案和转化效果。
- **变更影响面**：电销跟进、短信发送、客户转化。

### 6.13 电销配置可见性
- **业务作用**：控制该配置项是否对外（坐席、前端）可见。
- **默认/取值**：每项可设可见/不可见。
- **调整影响**：影响运营参数的对外透明度与权限隔离。
- **变更影响面**：运营参数对外透明度、权限隔离、权限合规。

### 6.14 配置分组
- **业务作用**：将配置项按业务分组管理（发现类、派单类、外呼类）。
- **默认/取值**：按分组归类。
- **调整影响**：影响配置维护的组织方式，不直接影响业务行为。
- **变更影响面**：配置维护组织方式。

> **配置体系说明**：电销配置以"编码 + 名称 + 取值 + 单位 + 可见性 + 分组"形态集中存储，运营可在管理端随时读取与更新；其中发现窗口、延迟、应用/平台范围均按"来源编码 + 后缀"的方式为每类来源独立配置。

> **业务影响范围**：自动展期比例、坐席上限、发现窗口直接影响催收与转化主流程；来源应用/平台范围影响各应用名单构成；状态提醒影响精准触达；可见性影响权限合规。
